Set up your Atlas

Installing Ubuntu (the OS under Atlas)

Two paths, depending on the hardware. Pick one, then both end at the same place: a black screen with a login prompt. After that you switch to your own computer for everything else — the “Switch to your own computer” section explains how.

Path A — regular PC

You need: the PC itself, an empty USB stick (8GB or bigger — it gets erased), another working computer, and an ethernet cable to your router.

1. Make the install USB (on any working computer)

  1. Download Ubuntu Server 24.04 LTS. Direct link (starts the download immediately): ubuntu.com/download/server/thank-you?version=24.04.4&architecture=amd64&lts=true. If that link has gone stale (version numbers move on), just go to ubuntu.com/download/server and take the LTS one.
  2. Download balenaEtcher from etcher.balena.io and open it.
  3. In Etcher: pick the Ubuntu file you downloaded → pick the USB stick → Flash. Everything on the stick is erased.

2. Boot the PC from the USB

  1. Plug in the ethernet cable and the USB stick. Power the PC on and immediately tap the boot-menu key over and over — usually F12 (sometimes F11, F8, or Esc; the very first splash screen names it, e.g. “F12 = Boot Menu”).
  2. Pick the USB stick from the menu.
  3. At the purple menu, choose “Try or Install Ubuntu Server”.

3. The installer screens, in the order they appear

Arrow keys move, Enter selects, Tab gets you to “Done”.

  1. Language — English.
  2. Keyboard — leave defaults → Done.
  3. Type of install — keep “Ubuntu Server” (do NOT pick “minimized”) → Done.
  4. Network — wait until the wired connection shows an address like 192.168.x.x, then Done.
    If no address ever appears, stop

    Reseat the ethernet cable or try another port on the router. Do not continue without an address; the install would finish but the machine would be offline. (A previous install hit exactly this — a network port that quietly refused to connect.)

  5. “Installer update available” — if this screen appears, choose “Update to the new installer” and let it download. It shows up whenever Canonical has shipped installer fixes since the disc image was made, which is most of the time — it does not mean your download was old.
  6. Proxy — leave empty → Done.
  7. Mirror — leave as-is, let its test finish → Done.
  8. Storage — the one screen where the default is wrong. Keep “Use an entire disk”, but UNCHECK “Set up this disk as an LVM group” → Done → Done again → Continue on the red warning. (The warning means the PC’s disk gets erased — that’s intended.) Why uncheck: the LVM default silently uses only ~100GB of the disk and hides the rest; a previous install left 800GB of a 900GB drive invisible this way.
  9. Profile — your name; the server’s name: one short lowercase word (this becomes your Atlas instance’s name — e.g. atlas); a username; a password you will remember. → Done.
  10. Ubuntu Pro — “Skip for now” → Continue.
  11. SSH — the second screen you cannot get wrong. Move the highlight to “Install OpenSSH server” and press Space or Enter so an X appears in the box — then Done. Without that X, your own computer cannot connect later and you’ll be stuck at the machine’s keyboard. (It only allows computers inside your own house to log in — nothing outside can reach it.)
  12. Featured server snaps — select nothing → Done.

4. Wait, then reboot

  1. The install runs (progress scrolls by). Wait for “Install complete!”, then choose “Reboot Now”.
  2. When it asks, pull the USB stick out and press Enter.
  3. The machine boots to a black screen ending in a login prompt. That is correct — there is no desktop on purpose. Log in with the username and password from step 3.9.

Path B — Raspberry Pi

You need: the Pi (a Pi 4 or newer with at least 2GB of memory), its SD card — or better, a USB-attached SSD — 16GB or bigger (it gets erased), another working computer, and an ethernet cable to your router.

1. Write Ubuntu onto the card (on any working computer)

  1. Download Raspberry Pi Imager from raspberrypi.com/software, install it, open it. (It’s the Pi makers’ official flashing app: it downloads the right Ubuntu for the Pi itself and lets you preset your username and the machine’s name before writing.)
  2. CHOOSE DEVICE → your Pi model (e.g. Raspberry Pi 4).
  3. CHOOSE OS → Other general-purpose OS → Ubuntu → Ubuntu Server 24.04 LTS (64-bit).
  4. CHOOSE STORAGE → the SD card / USB drive. Everything on it is erased.
  5. Click NEXT → it asks about OS customisation → EDIT SETTINGS:
    • hostname: one short lowercase word (this becomes your Atlas instance’s name — e.g. atlas)
    • a username and a password you will remember
    • on the Services tab: enable SSH, “use password authentication”
    Save, then YES twice — it downloads and writes.

2. Boot the Pi

  1. Put the card/drive in the Pi, plug in ethernet, then power. First boot takes a couple of minutes (it resizes itself; the screen may sit quiet — give it five minutes before worrying).
  2. It ends at a black screen with a login prompt. That is correct — there is no desktop on purpose. Log in with the username and password you set in Imager.

Switch to your own computer (both paths)

The machine’s own screen and keyboard were only needed to get the OS on. From here you work from your normal computer instead — a real window where you can copy, paste, and click links. Two things to collect first, at the machine:

  1. Its address. Right after you log in, the welcome text includes a line like IPv4 address for eno1: 192.168.1.x — write down that 192.168.x.x number. (If it has scrolled away, type hostname -I and press Enter; the first number it prints is the one you want.)
  2. Your username and password — the ones you created during the install. Same login from anywhere in the house.

Now, on your own computer, open the built-in terminal:

  • Windows: press the Windows key, type powershell, press Enter.
  • Mac: press Cmd+Space, type terminal, press Enter.

In that window, type (your username, the @ sign, then the address):

ssh yourusername@192.168.x.x

The first time, it asks whether to trust this machine — type yes and press Enter.

If you get a big “WARNING: REMOTE HOST IDENTIFICATION HAS CHANGED” block

That happens when the machine’s OS has been reinstalled — your computer remembers the old install. Not an attack in a home setting. Type this, then try the ssh line again:

ssh-keygen -R 192.168.x.x

(using the machine’s actual address).

If it says “Connection refused”

The OpenSSH box didn’t get ticked during the install. Fix it at the machine’s keyboard — log in there and type this one line, then come back to your own computer and try again:

sudo apt install -y openssh-server && sudo systemctl enable --now ssh

(That line fixes it whether the install step was skipped or the service just didn’t start.) Then it asks for your password (typing shows nothing on screen — that’s normal). You end up at the same prompt you saw on the machine’s own screen — you’re now driving it from your computer.

Every step from here on happens in this window, not at the machine. You can walk away from the machine itself; it just needs power and ethernet.

Install Atlas (both paths)

Two paste-chunks in the SSH window (right-click usually pastes in PowerShell).

First this line by itself — it asks for your password (your login password again; typing shows nothing):

sudo mkdir -p /opt/stack && sudo chown "$USER" /opt/stack

Then these three lines as one paste:

git clone https://github.com/ecpunk/atlas-framework.git /opt/stack/atlas-store
cd /opt/stack/atlas-store
./bootstrap.sh

Notes while it runs:

  • It asks for your password once or twice ([sudo] password for ...) — that’s your login password again.
  • It prints a login secret in a boxed message, shown only once — copy it somewhere safe. You’ll need it later if you connect your phone; if it’s ever lost, it can be regenerated, so don’t panic either way.
  • Right after a fresh install the system updates itself in the background. If the setup runs into that, it says so and waits (up to half an hour) instead of failing — let it sit.
  • It ends with a boxed “Your Atlas is up” message pointing you to the next section here.

Start your agent (both paths)

Still in the SSH window, type these two lines:

cd /opt/stack/atlas-store
claude

Starting it in that folder matters — it’s where the agent finds your Atlas.

If claude says “command not found”

Close the SSH window, connect again, and retry — the install landed in a folder your login predates.

The first run sets itself up and logs you in, screen by screen:

  1. It may ask you to “Choose the text style” — just press Enter.
  2. It may offer other display options (a “flicker-free” mode, and similar) — any answer is fine; these screens change with agent updates and none of them affect your setup.
  3. “Select login method” — choose 1, “Claude account with subscription”, and press Enter.
  4. It shows a long web link and waits for a code. Click the link (hold Ctrl and click in most terminals), or copy and paste it into your browser. Log in with your Claude account there.
  5. The browser hands you a code — copy it, paste it back into the terminal, press Enter.
  6. A couple of confirmation screens follow (security notes, and whether to trust this folder) — accept them.

Then, in that first session, type:

Read "Start Here.md" and introduce yourself.

That’s it. Anything else — reaching your Atlas from your phone, backups, fixing something that breaks — you just ask the agent for in plain words. It knows how, and it does the technical parts itself.

Good to know: leave the agent by typing /exit — that brings your normal prompt back. Close the SSH window afterwards by typing exit.
